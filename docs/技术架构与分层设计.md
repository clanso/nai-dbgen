版本 v1.0（设计稿）。配套文档：`宿主能力基线.md`（事实依据）、`../../docs/酒馆数据库生图插件需求.md`（需求）。

## 0. 需求符合性与实现约束

**需求文档无需变更。** 4.7 的 `<IMG>数字</IMG>` 正文格式、4.8 的两条酒馆正则，全部按原文实现。

本节只列四条**实现约束**——它们不改需求，但决定了实现方式，写错就出 bug。

### 0.1 两条正则按需求原文实现

| 脚本 | 配置 | 依据 |
| --- | --- | --- |
| 正则 1：slot → 控件 | `placement:[AI_OUTPUT]` + `markdownOnly:true` | 展示期跑，`script.js:1860` 传 `isMarkdown:true` |
| 正则 2：发送时剥 slot | `placement:[AI_OUTPUT]` + `promptOnly:true` | 出站期跑，`script.js:4501` 作用于 `coreChat`，不落盘 |

两条都由插件在激活时**程序化写入** `extension_settings.regex`，用户无需手动导入。
`getRegexScripts()` 是导出的（`regex/index.js:17`），启动时校验自己那两条是否被删改，缺失即补装。

**正则 1 的 `replaceString` 不是静态模板。** `runRegexScript` 的最后一步是
`return substituteParams(replaceWithGroups)`（`engine.js:443-444`），且顺序是
**先展开 `$1`，后跑宏**。所以 `{{naislot::$1}}` 会先变成 `{{naislot::3}}`，再调进插件注册的宏
handler，拿到 slot 号、查状态、返回状态相关 HTML。宏返回值**不做 HTML 转义**
（`MacroEngine.js:332-348` 只做 `String()` 归一），也不被二次扫描宏。

### 0.2 分工：正则吐骨架，JS 填内容

正则**只吐控件骨架**，不吐图片、不决定按钮状态：

```html
<div class="nai-slot" data-slot="$1">
  <button class="nai-slot-btn"></button>
  <div class="nai-slot-img"></div>
</div>
```

按钮文案（生图 / 重新生成）与图片由 JS 在渲染后填入。

分界线是**状态**：正则产物是静态骨架，一切随状态变化的东西都归 JS。
所以出图后只改那一个已挂载的节点，不需要重渲染整楼。

JS 挂载的节点是 `createElement` 出来的，**不经过 DOMPurify**，所以 `blob:` URL 可用、
`addEventListener` 可用、class 不被改名。

### 0.3 净化器会改三处，写 CSS 和事件时必须知道

`chats.js:1901-2051` 是唯一的 DOMPurify 钩子注册点。

| 写进去 | 出来变成 | 应对 |
| --- | --- | --- |
| `class="nai-slot"` | `class="custom-nai-slot"` | 靠 `data-slot` 属性定位，挂载时由 JS 补未加前缀的类名（§8.3） |
| `onclick="…"` | 被剥除 | `#chat` 上事件委托 |
| `<img src="blob:…">` | 大概率被剥除 | 不从正则出图片，见 §0.2 |

另有一条环境依赖：用户若开启 `encode_tags`（`power_user`，默认 false），
`<` `>` 在 showdown 之前就被转义，正则吐的 HTML 会变成可见文本。启动期探测，
命中则告警并降级为「正文可见 slot + 面板内出图」。

### 0.4 四个模板变量必须由插件自己替换

新宏引擎默认开启（`power-user.js:302`），标识符规则 `/^[a-zA-Z][\w-_]*$/` 无 `u` flag，
**CJK 被拒**。所以 `{{世界书}}` 走不通酒馆宏引擎。

需求 4.4 的中文变量名**原样保留**，由插件自己的替换器处理，另提供 ASCII 别名。
替换顺序是安全边界，见 §6.5——**先跑宿主宏，后注入四块**，否则块内容里的 `{{…}}` 会被当宏执行。

## 1. 架构目标

| # | 目标 | 可检验的落地方式 |
| --- | --- | --- |
| G1 | **宿主隔离**：ST 的版本敏感行为集中在一处 | `domain/` 目录零 ST 导入、零 `fetch`、零 DOM。ST 相关全部在 `adapters/host/` |
| G2 | **高内聚**：一个业务概念的规则只在一个模块 | 关键字匹配只有 `domain/matching/`；NAI 请求装配只有 `domain/nai/payload-assembler.js` |
| G3 | **低耦合**：依赖倒置，上层持接口不持实现 | 所有跨层依赖走 `ports/`；`bootstrap/container.js` 是唯一 new 实现的地方 |
| G4 | **可扩展**：新增库类型 / 新增传输 / 新增注入块不改既有代码 | §9 列出三个扩展点各自的开闭边界 |
| G5 | **可降级**：任一宿主能力缺失只损失对应功能 | 启动期能力探测表 + 每个降级路径的 UI 明示 |
| G6 | **可验收**：需求 §10 的 14 条能逐条自动化 | 领域层纯函数可单测；`GenerateSlotsUseCase` 断言 LLM 调用次数恰为 2 |

### 1.1 不做的事（明确排除，避免过度设计）

- 不引入构建工具链。交付物是浏览器可直接 `import` 的 ES module（需求 §8 约束）。
- 不做响应式框架。UI 用极薄的 store + 订阅，够用。
- 不做服务端插件、不注册 ST 路由（需求 §8 约束）。
- 不做跨设备同步。数据主存本机 IndexedDB，靠导入导出搬运。

## 2. 分层模型

五层，依赖**严格单向向下**。箭头即 import 方向，不允许反向、不允许跨层向上。

```
┌──────────────────────────────────────────────────────────────┐
│ L5  ui/           表现层                                      │
│     面板 / 工作台 / slot 控件 / 弹窗。只读 store，只发意图      │
└───────────────────────────┬──────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ L4  application/  应用编排层                                  │
│     用例 = 一次业务动作的完整时序。持有 ports，不含业务规则     │
└───────────────────────────┬──────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ L3  domain/       领域层   ★ 纯函数，无 IO，无宿主             │
│     匹配规则 / 注入块格式 / 模板渲染 / 请求装配 / slot 定位     │
└──────────────────────────────────────────────────────────────┘
                            ↑ 实现
┌──────────────────────────────────────────────────────────────┐
│ L2  adapters/     端口适配层                                  │
│     host(ST) / nai / llm / storage。脏活全在这里              │
└───────────────────────────┬──────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ L1  infra/        基础设施                                    │
│     Result / 错误体系 / 日志 / 事件总线 / ID / 轻量校验        │
└──────────────────────────────────────────────────────────────┘

     ports/   契约声明（纯 JSDoc typedef，无运行时代码）
              L3/L4 依赖它，L2 实现它 —— 依赖倒置的支点
```

### 2.1 依赖规则（可被 lint 强制）

| 层 | 允许 import | 禁止 import |
| --- | --- | --- |
| `domain/` | `infra/`、`ports/`（仅类型） | `adapters/`、`application/`、`ui/`、ST 任何模块、`fetch`、`document` |
| `application/` | `domain/`、`ports/`、`infra/` | `adapters/`（具体实现）、`ui/` |
| `adapters/` | `ports/`、`infra/`、`domain/`（仅模型与纯函数） | `application/`、`ui/` |
| `ui/` | `application/`(用例接口)、`infra/`、`domain/model` | `adapters/` |
| `infra/` | 无 | 一切 |

**为什么 `domain/` 的纯净是最重要的一条**：基线文档第 12 节列了 10 个版本敏感项。ST 每次升级都可能动其中几个。把业务规则关在 `domain/` 里，升级 ST 时**只需要改 `adapters/host/`**，业务逻辑与其测试一行不动。这是本架构最主要的风险对冲。

### 2.2 为什么不用更少的层

三层（UI / 业务 / 数据）在这个项目会立刻失控，因为存在两个独立的强耦合源：**ST 宿主**与**两个外部 API**。不把它们各自压成端口，业务代码里会同时出现 `getContext()`、`fetch('/proxy/...')` 和关键字匹配规则。L2/L3 的切分不是为了好看，是为了让 §0 里那五条变更能在**单个目录内**被吸收。

## 4. 端口契约

端口是**领域和用例对外界的全部期望**。冻结这些签名，L2 与 L3 就能独立演进。

### 4.1 HostPort —— 唯一的酒馆面

```js
/**
 * 酒馆宿主端口。这是插件对 SillyTavern 的全部依赖面。
 * 只有 adapters/host/sillytavern.host.js 实现它。
 * ST 升级导致的破坏被限制在该实现内。
 */
export const HostPort = {
  // —— 聊天读取 ——
  /** @returns {ChatId|null} */                     getCurrentChatId,
  /** @returns {HostMessage[]} 全部楼，下标即 messageId */ getMessages,
  /** @param {number} n @returns {HostMessage[]} 最近 n 条 AI 回复楼，新→旧 */
                                                    getRecentAiMessages,
  /** @returns {HostMessage|null} */                getMessage,        // (messageId)

  // —— 楼层正文写入（唯一允许改正文的入口）——
  /** @returns {Promise<Result<void>>} */           replaceMessageText, // (messageId, newText)
  /** 重绘某楼 DOM */                                rerenderMessage,   // (messageId)

  // —— 楼层元数据（slot 权威记录的载体）——
  readMessageExtra,      // (messageId) → object
  writeMessageExtra,     // (messageId, patch) → Promise<Result<void>>

  // —— 渲染挂载 ——
  /** 注册 afterMarkdown 文本变换。返回取消函数 */
  ensureSlotRegexInstalled, // 写入/校验/补装两条正则脚本
  /** 每当某楼 DOM 出现/被重建时回调，保证幂等与不遗漏 */
  onMessageDomReady,       // (fn: (messageEl, messageId) => void) => Unsubscribe

  // —— 出站提示词拦截 ——
  registerOutboundTransform, // (fn: (mes, msgMeta) => string) => Unsubscribe

  // —— 世界书 ——
  /**
   * 用调用方给定的上下文窗口跑酒馆自己的扫描器，副作用已隔离。
   * 必须收 contextWindow 而不是楼号：§6.3 要求世界书与角色、标签
   * 由同一个窗口派生，只传楼号会让适配器自建扫描窗从而与
   * ContextCollector 漂移。messageId 仅用于日志与 trace。
   * 「是否带发言人名」由适配器读酒馆 world_info_include_names 决定，
   * 属宿主知识，不上浮到 application。
   */
  resolveWorldInfo,        // ({contextWindow: HostMessage[], messageId?}) → Promise<Result<string>>

  // —— 生命周期事件 ——
  onChatChanged,           // (fn) => Unsubscribe
  onAiMessageSettled,      // (fn: (messageId) => void) => Unsubscribe  流式结束后才触发

  // —— 配置持久化（小配置）——
  loadSettings,            // () => PluginSettings   见 domain/model/plugin-settings.js
  saveSettings,            // (PluginSettings) => void   debounced

  // —— UI 宿主 ——
  mountSettingsPanel,      // (element) => void
  openModal,               // ({title, element, wide}) => Promise<void>
  registerSlashCommand,    // (spec) => void
  toast,                   // (level, message) => void
};
```

**设计要点**：端口用**业务语言**而非 ST 语言。`onAiMessageSettled` 而不是暴露
`CHARACTER_MESSAGE_RENDERED`；`onMessageDomReady` 而不是暴露 `MutationObserver`。
这样 §0 的机制替换不会泄漏到上层——上层只知道"某楼 DOM 好了"，不知道它是靠事件还是靠观察器得来的。

## 6. 关键机制设计

### 6.1 Slot 渲染：正则吐骨架 + 观察器幂等挂载

两个阶段，各自单一职责。

**阶段 A · 正则替换（`assets/regex/slot-to-widget.json`）**

展示期正则，`placement:[AI_OUTPUT]` + `markdownOnly:true`，由插件程序化写入
`extension_settings.regex`。它跑在 `messageFormatting` 第 5 步——**早于 showdown（第 9 步）
和 DOMPurify（第 11 步）**，所以 `<IMG>` 标签根本不会活到被解析成 `<img>` 元素那一刻。

```
findRegex:      /<IMG>\s*(\d+)\s*<\/IMG>/g
replaceString:  <div class="nai-slot" data-slot="$1">
                  <button class="nai-slot-btn"></button>
                  <div class="nai-slot-img"></div>
                </div>
```

骨架**不含状态、不含图片**（理由见 §0.2）。按钮无文案、图片容器为空，都由阶段 B 填。
净化后 class 变成 `custom-nai-slot`，所以定位靠 `data-slot` 属性而不靠 class；
挂载时 JS 再补未经净化的类名，CSS 因此不必写前缀（§8.3）。

正则脚本在用户手里（可禁用/编辑/删除/改顺序，别的全局正则也可能先动 `<IMG>`），
所以启动期用 `getRegexScripts()` 校验并补装。

**阶段 B · DOM 挂载（`adapters/host/slot-mount.observer.js`）**

`MutationObserver` 观察 `#chat` 的 `childList + subtree`，加一次初始全扫。
回调做**幂等对账**：找出所有 `div[data-slot]`，凡未打 `data-nai-mounted` 的，
从 store 读 `(messageId, slotId)` 状态，填按钮文案（生图 / 重新生成）并把图片塞进容器。
挂载出的节点用 `createElement`，**不经过 DOMPurify**，所以 `blob:` URL 与 `addEventListener` 都可用。

**为什么用观察器而不是事件订阅**：基线 §3 证明 `printMessages` 批量建 DOM 时不发任何
`*_MESSAGE_RENDERED`（初次进聊天、上滑懒加载都走这条），而流式输出期间 `.mes_text.innerHTML`
被高频整体替换且发生在 rendered 事件**之前**。六条不同的 `.mes_text` 覆写路径（基线 §3.1）
意味着任何"订阅 N 个事件"的方案都是在追赶一个会继续变化的清单。观察器把 N 条路径收敛成
一条不变量：**DOM 变了就对账**。幂等性让重复触发无害。

事件订阅仍保留，但只作为**快速路径**降低首帧延迟，不承担正确性。

**状态更新**：出图后只改已挂载的那个节点，不调 `updateMessageBlock`——避免整楼重渲染。

**降级**：若探测到 `encode_tags` 开启（正则吐的 HTML 会变成可见文本），
或正则扩展被整体禁用（`disabledExtensions.includes('regex')` 会短路 `getRegexedString`），
则降级为「正文可见 slot + 面板内出图」并告警。

### 6.2 Slot 剥离：出站正则

展示期正则的兄弟脚本，`placement:[AI_OUTPUT]` + `promptOnly:true`，同样程序化写入。
它跑在 `script.js:4501`，作用于 `coreChat`（生成副本），**磁盘原文保留 slot**——
正是需求 4.8 对正则 2 的要求。

剥离正则与阶段 A 的识别正则**共用** `domain/slot/slot-token.js` 的同一份定义——
两处若漂移就会出现"界面有按钮但模型看得见 slot"的隐性 bug。

`generate_interceptor` 作为**兜底**保留（manifest 已声明 `NaiDbGen_StripSlots`）：
它在出站正则**之后**执行（`script.js:4562` vs `:4501`），做一次幂等复查，
捕获"用户把正则 2 删了"这种情况。两者叠加不会重复剥离，因为剥完就没得剥了。

### 6.3 世界书：当前视角解析（`application/worldinfo-resolver.js`）

按可信度降序尝试，命中即返回，并向上报告来源等级。

**要取的不是历史记录，而是当前视角。**

酒馆生成第 N 楼时，扫描的是 chat[0..N-1]——那份激活结果描述的是**上一个场景**。
而插件生图时第 N 楼的正文已经存在。如果这一楼刚进了新场景，对应的世界书条目在生成 N 时
根本没被激活（文本里还没出现那个词），但生图恰恰需要它。

所以要扫的是**含第 N 楼的当前文本**，扫描对象就是本插件的「当前上下文」窗口。

**一个上下文窗口喂三个派生块。** 这是本设计的一条内聚原则：

```
ContextCollector: 最近 N 条 AI 回复楼（4.6，N 可配，默认 5，剥掉 <IMG>）
        │
        ├──→ 【当前上下文】块      直接作为变量值
        ├──→ 【世界书】块          用它跑酒馆扫描器
        ├──→ 【角色库】块          用它做关键字匹配（需求 4.1 明文规定）
        └──→ 【标签库】块          用它做 LLM 召回（需求 4.11 明文规定）
```

需求 4.1 与 4.11 已经把角色匹配和标签召回的扫描对象钉在「当前上下文」上了。
世界书若改用别的窗口（例如全量 chat + 酒馆的 `scanDepth`），四个块就会描述不同范围的场景，
而它们本该共同描述**同一张要画的图**。所以世界书也用这个窗口。

**实现**：调 ST 自己的 `getWorldInfoPrompt`，`chat` 参数传这个窗口。

```js
// chat：字符串数组、最新在前。
// 注意不要 reverse：script.js:4624 之所以 reverse，是因为它的 coreChat 是旧→新；
// 而 HostPort 约定 contextWindow 已经是新→旧，再 reverse 会把扫描序颠倒。
// 是否带发言人名读酒馆的 world_info_include_names——这属宿主知识，
// 判断放在 adapters/host/ 里，不上浮到 application。
// 该设置不在 getContext() 上，需从 /scripts/world-info.js 取（默认 true）。
const scanInput = contextWindow.map(m =>
    includeNames ? `${m.name}: ${m.text}` : m.text
);

await getWorldInfoPrompt(scanInput, maxContext, /* isDryRun */ true, globalScanData);
// globalScanData: { personaDescription, characterDescription, characterPersonality,
//                   characterDepthPrompt, scenario, creatorNotes, trigger:'normal' }
```

条目级的 `scanDepth` 仍然生效，只是在这个窗口**之内**收窄——N 是上限。
`<IMG>` slot 在 ContextCollector 里已剥掉（需求 4.6），所以 slot 数字不会误命中世界书关键字。

**两个已知后果**（由"只取 AI 回复楼"这条需求推导而来，非缺陷）：

1. 关键字只出现在用户楼或系统楼里的世界书条目不会激活。需求 4.6 明确当前上下文不含用户楼、系统楼。
2. 窗口外的世界书条目不会激活，即使它的 `scanDepth` 设得很大。N 是硬上限。

调的是酒馆的函数，不是自研扫描器，满足需求"不在插件里重扫"的约束本意。
「世界书」块的值取 `worldInfoString`（= `worldInfoBefore + worldInfoAfter`，两者之间**无分隔符**）。

**副作用隔离（必做，不是可选项）**

这条调用现在是每次生图都走的主路径，所以基线 §6.2 记录的副作用必须处理：

| 副作用 | 处理 |
| --- | --- |
| 改写作者注释 `setExtensionPrompt(NOTE_MODULE_NAME,…)`，**未受 isDryRun 保护** | 调用前快照 `extensionPrompts[NOTE_MODULE_NAME]`，调用后恢复 |
| `resetExternalEffects()` 无条件清 `externalActivations` | 记录为已知交互；会清掉其他扩展强制激活的条目 |
| `#ensureChatMetadata()` 初始化 `chat_metadata.timedWorldInfo` 结构 | 结构性初始化，无害 |
| sticky/cooldown 在 dryRun 下**不推进** | 正是期望行为 |
| 不发 `WORLD_INFO_ACTIVATED` | 正是期望行为，避免干扰其他扩展 |

带概率的条目（`probability`）每次扫描结果可能不同，所以解析出的世界书文本要
**写进 SlotRecord**，供复现与审计。

### 6.4 关键字匹配（`domain/matching/`）

`matchKeys` 未从 ST 导出（基线 §6.4），必须复刻。但 `parseRegexFromString` 与 `escapeRegex`
**是导出的**，直接 import 复用，保证正则键与转义语义零漂移。

复刻时必须命中的五个易错点（已在基线 §6.4 列明）：`\W` 而非 `\b`、多词键绕过全词、
**空键必须前置过滤**（`includes('')` 恒真）、正则键覆盖两个开关、全局默认值来源。

激活顺序（需求 4.1，不可调换）：**先按组过滤 → 再跑关键字**。
未激活组的角色根本不进入匹配循环，而不是匹配完再过滤。

### 6.5 预设渲染（`domain/template/`）

替换顺序是**安全边界**，不是风格问题：

```
1. 先让宿主宏跑：substituteParams(模板)      → 解析 {{char}} {{user}} {{time}} …
2. 再注入四个块：插件自己的替换器            → {{世界书}} {{当前上下文}} {{角色库}} {{标签库}}
```

**必须是这个顺序**。反过来的话，块内容（来自世界书、聊天正文、用户填的标签）里如果含 `{{...}}`
就会被宿主宏引擎当宏执行——这是一条注入面。先跑宿主宏、后注入块，块内容永远是惰性文本。

变量映射表 `variable-map.js` 同时登记中文名与 ASCII 别名（`{{worldbook}}` 等），
两者指向同一个块。中文名是需求 4.4 钦定的主名。

「某块为空则为空」（需求 4.4）：空块展开成空串，不做省略整段的智能处理。

### 6.6 NAI 请求装配（`domain/nai/payload-assembler.js`）

4.14 的唯一装配点，纯函数。**操作顺序由需求锁死**（需求 4.14「顺序」段）：

```
1. 取调用方原文 caption（base_caption + char_captions）
2. 【若开关为开】角色关键字原位替换成固定特征
   —— 非固定特征不参与；正负面都替换；固定特征内若再现关键字不做第二遍
3. 拼当前激活画师串：正向/负向各接到 base_caption 最前面，", " 连接
   —— 原文为空则字段等于画师串本身，不补逗号
   —— char_caption 与 centers 不动
   —— 画师串不参与步骤 2 的替换（因为在其之后）
4. 写入五个固定结构开关（FIXED_STRUCTURE）
5. input ← 正向 base_caption 整段；negative_prompt ← 负向 base_caption 整段
6. 合并 4.13 参数：调用方传入的逐字段覆盖，未传的用 4.13；
   调用方多传的 NAI 原生字段原样带上不删
```

步骤 2、3 的先后是有意义的：画师串在替换之后拼，所以画师串里的字不会被拿去匹配关键字。
这条写进 `artist-prefix.js` 的注释，因为它是唯一无法从代码形状看出来的约束。

**质量词策略开关**（§0.6）：`QualityInjectionStrategy` 在此分叉，`field` 走
`qualityToggle/tag_hint_qt/ucPreset/tag_hint_uc_preset` 字段，`caption` 走文本拼接。

### 6.7 NAI 传输：策略矩阵 + 自检

需求约束不能加 ST 路由，而 ST 自带的 NAI 路由无法传 `v4_prompt`（基线 §8.1）。
剩下两条通道，正交于两种响应解码方式：

| 传输 | 机制 | 前置条件 | 风险 |
| --- | --- | --- | --- |
| `direct` | 浏览器直接 fetch 配置的 baseUrl | 对端返回 CORS 头 | **官方 NAI 的 CORS 行为未实测**；第三方中转通常可控 |
| `st-cors-proxy` | `POST /proxy/<url>` | 用户开启 `enableCorsProxy` | 需用户改 config.yaml 或加 `--corsProxy` |

| 解码 | 机制 | 触发 |
| --- | --- | --- |
| `json-base64` | `Accept: application/json` → base64 数组 | 首选，浏览器侧零解压 |
| `zip` | `DecompressionStream('deflate-raw')` 手工解 ZIP | 对端忽略 Accept 时兜底；**用浏览器原生 API，不引第三方库** |

`Accept: application/json` 是官方支持的（`docs/nai-official/接口文档.md:529` 明确 201 返回
base64 图片数组），优先用它可以完全绕开在浏览器里解 ZIP。

**连通性自检**：每条 NaiApiConfig 提供「测试」按钮，依次探测两种传输与两种解码，
把可用组合写进配置。这把一个**无法静态回答的问题**（CORS 到底通不通）转成
一次用户可见的运行时探测，而不是把架构押在猜测上。CORS 不通时 UI 直接给出
开启 `enableCorsProxy` 的指引。

### 6.8 LLM 传输：宿主后端优先

```js
getContext().ChatCompletionService.sendRequest({
  chat_completion_source: 'openai',
  reverse_proxy: config.baseUrl,     // ← 逐次请求自带地址
  proxy_password: config.apiKey,     // ← 逐次请求自带密钥
  model: config.model,
  messages, max_tokens, temperature,
  json_schema: schema,               // → 服务端转 response_format
})
```

基线 §8.4 已验证这条路径**不碰用户全局设置、不需要连接配置档、走 ST 服务端因此无 CORS 问题**。
这是本项目唯一一个"外部 API 调用完全没有未知风险"的地方，定为默认。
`direct` 传输保留给想绕开 ST 服务端的用户。

`json_schema` 用于两处刚需：步骤 5 的 `[{slotid, 生成点, 生图内容}]` 数组，
以及召回的 key 列表。同时 `json-extract.js` 做容错兜底（剥 markdown 围栏、截取首个
平衡的 JSON 块），因为第三方中转常常不支持结构化输出。

### 6.9 存储分层

| 数据 | 载体 | 理由 |
| --- | --- | --- |
| 小配置、激活选择、四个当前选中项 | `extension_settings['nai-dbgen']` | 随账号走；体积须控制在数 KB |
| 四个库、预设、API 配置 | **IndexedDB** | 基线 §9：`extension_settings` 会导致整个 `settings.json` 每次全量重写 |
| slot 权威记录（caption + 图片引用） | **`message.extra['nai-dbgen']`** | 随 swipe 克隆进 `swipe_info`（基线 §9），随聊天导出走；天然按楼作用域 |
| 图片二进制 | **IndexedDB blob** | 避开 ST「Data Maid」把未被 `extra.media` 引用的图片列为可删（基线 §9） |
| slot 检索索引 | IndexedDB（可从 `message.extra` 重建） | 供「生图提示词管理」面板查询；派生数据，丢了能重建 |

API Key 存 IndexedDB 明文，与现有桌面项目一致（`app/public/key-vault.js`），
并在 UI 明示需求 §8 已承认的风险：Key 出现在浏览器侧。

**不写 `extra.media`** 是刻意的——需求明确"图片不写入楼层正文"，写 media 会让图片
出现在 ST 原生的媒体容器（`.mes_media_wrapper`，是 `.mes_text` 的兄弟节点，基线 §9.1），
位置也不符合"按钮下方"。代价是放弃 Data Maid 的保护，用 IndexedDB 自管生命周期补偿。

## 8. UI 设计（承接本地项目）

UI 继承 `app/public` 的设计语言，但**不能照搬**：本地项目是全页独占、纯浅色、自带调色板的应用，
而本插件寄生在酒馆页面里，酒馆拥有页面骨架且用户常开深色主题。

### 8.1 继承什么、丢弃什么

| 继承（家族基因） | 丢弃（全页独占假设） |
| --- | --- |
| 强调色 `#c13d75` / `#aa2f65` 与激活态语言 | `:root` 上的全局配色、字体、背景 |
| 控件词汇 `.button` / `.button-primary` / `.button-ghost` / `.chip-button` / `.text-button` | `.app-shell { height:100dvh }`、`body{overflow:hidden}` |
| 控件尺寸令牌 28 / 32 / 36 / 40px + `--control-radius:10px` | 固定顶栏 `.suite-topbar` + 移动底部导航 `.mobile-nav` |
| 库管理范式：搜索 + 分类/标签筛选 + 卡片网格 + 模态编辑器 + 导入预览表 | 三页面 + `.suite-nav` 跨页导航 |
| 当前项选择器：封面缩略图 + 搜索 + 结果列表 + `.active` 高亮 + 清除 × | 满屏 `backdrop-filter` 对话框 |
| `.toggle-row` / `.range-label` / 字段组表单范式 | `html.android-app` / `html:not(.android-app)` 宿主类耦合 |
| `<details>/<summary>` 折叠次要设置 | 在 `document.documentElement` 上写 CSS 变量 |
| 空状态 / 内联错误区 / 删除确认 | `document` 级 `nai-*` 事件总线 |

本地项目**没有**深色主题（`index.html:6` 锁 `color-scheme: light`），所以配色不能直接用。

### 8.2 令牌策略：结构跟酒馆，身份留自己

两层令牌，全部定义在 `#nai-dbgen-root` 下，**绝不碰 `:root` / `html` / `body`**。

```css
#nai-dbgen-root {
  /* 表层：跟随酒馆主题，保证在任何主题下都不突兀。均带兜底值 */
  --nd-text:      var(--SmartThemeBodyColor, #4b3040);
  --nd-surface:   var(--SmartThemeBlurTintColor, #fffdfd);
  --nd-surface-2: var(--SmartThemeBotMesBlurTintColor, #fff0f6);
  --nd-line:      var(--SmartThemeBorderColor, rgba(123, 70, 96, .21));
  --nd-muted:     var(--SmartThemeEmColor, #7f5f70);
  --nd-shadow-c:  var(--SmartThemeShadowColor, rgba(123, 70, 96, .16));

  /* 身份层：家族基因，不跟主题变 */
  --nd-accent:      #c13d75;
  --nd-accent-deep: #aa2f65;
  --nd-accent-soft: #f47eae;
  --nd-danger:      #d94f72;

  /* 形状与尺寸：照搬本地项目 */
  --nd-radius: 18px;  --nd-control-radius: 10px;
  --nd-h-micro: 28px; --nd-h-icon: 32px; --nd-h: 36px; --nd-h-primary: 40px;

  /* 字号跟宿主缩放，字族留自己 */
  font-size: var(--mainFontSize, 15px);
  font-family: Aptos, "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif;
  box-sizing: border-box;
}
#nai-dbgen-root *, #nai-dbgen-root *::before, #nai-dbgen-root *::after { box-sizing: inherit; }
```

**身份来自强调色 + 控件词汇 + 交互范式，不来自背景色。** 这样在深色主题下依然成立，
也不需要维护两套配色。上面六个 `--SmartTheme*` 变量名已对 `ref/SillyTavern/public/style.css` 核实存在。

字族沿用本地项目的 `Aptos, "Microsoft YaHei UI", "PingFang SC"`（酒馆默认的 Noto Sans 中文表现差），
标题的 Georgia 衬线点缀保留。

**但字号不能照搬本地项目的硬编码值。** 酒馆有用户可调的 `--fontScale`
（`--mainFontSize: calc(var(--fontScale) * 15px)`），硬编码 12px 会让插件在放大字号的用户那里
显得比宿主小一号。所以根节点取 `--mainFontSize`，内部一律用 `em` 相对表达
（本地项目的 12px 正文 ≈ `0.8em`，11px 辅助 ≈ `0.73em`）。控件高度令牌保持像素固定，
因为它们决定触控靶区，不该随字号漂移。

### 8.3 两个 CSS 命名空间（关键，极易踩）

插件的 UI 分布在两个环境，净化规则不同：

| 环境 | 是否过 DOMPurify | class 是否被改名 | 写法 |
| --- | --- | --- | --- |
| 面板 / 工作台 / 弹窗 | ❌ 不过 | 否 | 正常写 `.nd-button` |
| **楼层内 slot 控件** | 骨架过，挂载产物不过 | **骨架的 class 被加 `custom-` 前缀** | 见下 |

**解法：靠 `data-*` 定位，靠 JS 补类名。**

正则骨架只依赖 `data-slot` 属性（`data-*` 不受净化影响），挂载时由 JS 用
`createElement` 建子节点并给根节点补上**未加前缀**的 `nd-slot` 类。
于是除了一条「挂载前占位」的兜底样式，**全部 CSS 都不需要写 `custom-` 前缀**：

```css
/* 唯一需要前缀的一条：挂载完成前的占位，避免无样式闪烁 */
.custom-nai-slot { min-height: 34px; }
/* 挂载后（JS 补的类，未经净化） */
.nd-slot { … }  .nd-slot__btn { … }  .nd-slot__img { … }
```

这比「所有 CSS 都按 `custom-` 前缀写」干净得多，也不会在重构时漏改。

### 8.4 界面宿主映射：三页面 → 一抽屉 + 一弹窗

本地项目的三个页面（绘图 / 助手 / 实验室）不能直接搬。需求 §6 要求七个管理界面 + 工作台。

| 宿主位置 | 装什么 | 依据 |
| --- | --- | --- |
| **酒馆设置抽屉**（`#extensions_settings2` 内一个 `.inline-drawer`） | 高频开关与当前选择：上下文楼数、两个自动开关、当前画师串 / 当前 NAI / 两个 LLM 选择、一个「打开管理台」按钮 | 抽屉空间窄，只放常调项 |
| **管理台**（酒馆 `Popup`，`wide + large + allowVerticalScrolling`） | 七个管理界面做成**弹窗内标签页**，结构照搬本地项目 `.lab-tabs` | 基线 §11 |
| **生成工作台** | 同一个 Popup 里的一个标签页，或独立 Popup | 需求 4.15 要求「独立页面，不挂在某一楼」 |
| **楼层内** | slot 控件（按钮 + 图片） | §6.1 |

用酒馆的 `Popup`（`callGenericPopup`）而不是本地项目的原生 `<dialog>`：能正确参与酒馆的
层叠顺序与移动端行为。**但 Popup 里面的内容全部用本地项目的组件配方**——
外壳跟宿主，内容跟家族。

### 8.5 库管理界面：直接复用本地项目的范式

四个库（角色 / 标签 / 画师串 / API 配置）共用一套布局，就是本地项目实验室那套：

```
┌ 工具栏 ────────────────────────────────────────────┐
│ 搜索框 │ 分组筛选 │ 类型筛选 │ 仅看启用 │ ＋新建 │ 导入 │ 导出 │
└────────────────────────────────────────────────────┘
┌ 卡片网格 grid-template-columns: repeat(auto-fill, minmax(260px,1fr)) ┐
│ [封面/首字母] [启用开关] [名称] [编辑 复制 删除]                      │
└──────────────────────────────────────────────────────────────────────┘
```

照搬的具体范式：
- **编辑用模态**，不用内联表单（本地项目 `#editDialog`）
- **导入**支持拖放 + 文件选择 + 粘贴，先出**预览表**再确认，带重复处理策略（跳过/覆盖/另存）
- **封面**用 `aspect-ratio` + `object-fit: contain`，缺图时退化为首字母花体占位
- **删除确认**：批量走确认框，单条危险操作走专用确认弹窗
- **激活态**：`.active` 加强调色边框 + 浅强调色底

针对本插件的三处改进（本地项目没有，但这里需要）：

| 改进 | 原因 |
| --- | --- |
| **组/库的启用开关做成一等公民** | 需求 4.1/4.3 的「组激活」「库激活」直接决定计算范围，本地项目只有「当前选中」没有「启用」语义 |
| **标签条目列表虚拟化或分页** | 本地项目全量重建 DOM（`renderLibrary` 每次重拼整个 innerHTML），标签库可能上千条 |
| **角色库两层结构**（组 → 角色） | 本地项目是扁平列表 + 分类筛选，需求要求真正的两层容器 |

### 8.6 反馈与状态

| 场景 | 做法 |
| --- | --- |
| 瞬时提示 | 用酒馆的 `toastr`（经 `HostPort.toast`），与宿主通知同栈；**不**做本地项目那个 `position:fixed` 的 `.toast-region` |
| 表单级错误 | 内联错误区，沿用本地项目 `.modal-message` / `.parse-warnings` 范式 |
| 生图进度 | slot 控件内就地显示进度；工作台显示队列进度 |
| 长链路失败 | 按 §10 的 `AppError` 分类给出可操作指引，并附 traceId |

### 8.7 状态 → UI 接线

本地项目是「模块级 `state` 对象 + 命令式 DOM 操作 + `els` 引用缓存」，无框架。
本插件沿用这个量级，但补两处：

1. **订阅式 store**（`ui/common/store.js`）：仓库变更 → 通知订阅者 → 局部重绘。
   本地项目靠手动调 `renderLibrary()`，容易漏；slot 控件散落在楼层里必须靠订阅。
2. **内部事件总线**（`infra/event-bus.js`）用于 L4→L5，**不用 `document` 级 CustomEvent**。
   对外给其他酒馆插件的事件才挂 `document`，且命名空间 `nai-dbgen-*`，避免与本地项目的
   `nai-*` 撞名（两者理论上可能在同一浏览器里共存）。

### 8.8 文案与可访问性

- 中文硬编码，与本地项目一致；但全部文案过一层 `ui/i18n/zh-CN.js` 字典，留出提取口子，不做完整 i18n
- 移动端不移植本地项目的断点体系，改用容器查询 + flex 换行，并读取 `getContext().isMobile`
- 可访问性按本地项目的水平做（`aria-label`、`aria-live` 用在状态区、`focus-visible` 描边），不额外投入

## 9. 三个扩展点

G4 的具体兑现。每个扩展点都有明确的开闭边界：新增时**只加文件，不改既有文件**。

| 扩展点 | 新增内容 | 需改动的既有文件 |
| --- | --- | --- |
| **新增传输通道**（如自建中转、Tauri 原生请求） | `adapters/nai/transport/<name>.js` 实现 `Transport` 接口 | 仅 `container.js` 注册表加一行 |
| **新增注入块**（如"角色关系图"第五块） | `domain/blocks/<name>.block.js` + `variable-map.js` 加一项 | 仅 `variable-map.js`；`BlockSet` 用字典不用固定四字段 |
| **新增库类型** | `domain/model/<x>.js` + `adapters/storage/repos/<x>.repo.js` + `ui/panels/<x>/` | 仅 `container.js` |

为此，`BlockSet` 必须设计成 `Map<variableName, string>` 而不是
`{worldInfo, context, character, tag}` 四个具名字段——否则第五块会迫使整条链路改签名。
这是为扩展性付出的唯一一处设计代价，很便宜。

## 10. 错误处理与可观测性

**跨层用 `Result<T,E>` 而非异常**。理由：一次生图链路有 8 个可失败点（世界书降级、
召回 LLM、JSON 解析、提示词 LLM、生成点定位失败、CORS、NAI 429、图片存储），
用异常会让用例退化成一个大 try/catch，无法区分"降级继续"与"中止"。

```js
AppError 分类树
├─ HostError        宿主能力缺失/API 变更     → 明示降级，不重试
├─ ConfigError      用户没配/配错             → 指向对应设置项
├─ TransportError   CORS / 网络 / 超时        → 可重试，附诊断指引
├─ UpstreamError    401/403/429/5xx          → 按码区分：401 停用配置，429 退避
├─ ContractError    LLM 输出不符合约定         → 保留原始回文供用户查看
└─ DomainError      生成点匹配不上等业务失败    → 明确告知哪一项失败
```

沿用现有桌面项目的上游错误处置经验（`docs/技术架构分析.md` KeyPool 表）：
401/403 停用该配置、429 尊重 `Retry-After` 否则指数退避、408/5xx 退避重试、
用户中断不重试。这套是实战验证过的，直接继承。

**可观测性**：每次生图链路生成一个 `traceId`，串起两次 LLM 调用与一次 NAI 调用。
「生图提示词管理」面板按 traceId 展示：四个块的实际内容、渲染后的完整提示词、
LLM 原始回文、最终 NAI 请求体。这个面板同时是**需求验收 #2/#4/#5 的检验工具**——
能直接看出"预设未引用的块有没有泄漏进提示词"。

| **R-09** | 流式输出期间高频 `innerHTML` 覆写导致挂载抖动 | 低 | 观察器对账加去抖；流式中不挂载，`onAiMessageSettled` 后再挂 |
| **R-10** | 本地项目配色是纯浅色，用户主题千变万化（含自定义 CSS） | 中：可读性崩坏 | §8.2 双层令牌，表层绑 `--SmartTheme*`；验收时在酒馆默认深色 + 浅色 + 一个高对比主题下各走一遍 |
| **R-11** | 酒馆自定义 CSS 或其他插件的样式穿透进本插件面板 | 低 | 全部选择器挂 `#nai-dbgen-root` 前缀，不用裸标签选择器；关键控件显式声明继承属性 |

## 12. 实施路线图

按**风险优先**而非功能优先排序：先把不确定的地基验完，再堆功能。

| 里程碑 | 内容 | 出口条件 |
| --- | --- | --- |
| **M0 地基验证** | 骨架 + `capabilities.js` + slot 锚点钩子 + 观察器挂载 + 拦截器剥离 + NAI 连通性自检 + `tokens.css` 在三种主题下验证 | 正文 `<IMG>1</IMG>` 能变成可点按钮；出站提示词里无 slot；**R-01 有明确结论**；**R-10 有明确结论** |
