## 用户行为

1. 正文图片放大后，显示该图片编号的生成历史；顶部缩略图、前后按钮及左右方向键切换，Esc 关闭。不同编号不混为一组。已被缓存清理的历史图片不能恢复。
2. 工作台放大图使用累计历史，最近 50 张保存在本机图片缓存中；关闭再打开工作台可恢复。超过上限只淘汰最旧的工作台历史，不删除正文图片。
3. 在 NAI API 库保存多个配置，使用相同接口地址、不同 Key，并在触发设置开启“并行出图”。每个不同 Key 最多一路正在执行的请求；三 Key 可同时处理三项生图任务。重复 Key 不增加并发，其他接口地址不加入当前池。正文、工作台与画师预览共用池，关闭并行出图时整个池串行。
4. 双击 AI 回复正文空白处打开本楼提示词编辑器。可编辑提示词、尺寸、解析；保留图片历史。支持单条删除、勾选删除及右上角“全部删除”。全部删除仅影响当前楼，不是全会话；删除立即保存，文字编辑点击“保存”才生效。
5. 删除提示词同时移除正文对应的 `<IMG>` 标记，不修改其他正文、不主动删除历史图片 Blob。清除该编号的最新图缓存索引，避免编号复用误显旧图。
6. 手动启动本楼生图，若已有图片则第一次只显示 toast、不请求付费接口；再次启动，使用现有提示词重新生成并追加历史，不弹确认窗。无成功图片的失败任务可直接重试。自动生成仍跳过已有图片，不自动强制重出。

## 实现与安全边界

- 新增 application/nai-request-pool.js：按凭证分配、排队取消、释放和容器销毁。凭证只在现有配置与内存调度中使用，不写日志。
- image-gen.service 统一接入池；上游原有重试与限流逻辑保留，重试期间该 Key 保持占用。队列真正发起请求前检查原会话。
- 并发数是客户端上限，不是上游额度保证。多个 Key 若属于同一受限账户，上游仍可能限流。一次只有一项任务不会为了用满 Key 自动复制请求。
- slot.repo 对写操作的整个读改写过程排队，避免并发完成时覆盖其他图片历史。
- render-slot 延迟批量落盘前也记住待写图片；保存失败后的重试优先写回已生成图片，避免再次请求 NAI。
- slot-editor.service 使用正文快照与记录快照检测冲突。当前楼生成中、存在待写图片或编辑保存中时拒绝冲突操作；切聊拒绝保存。保存正文失败时尝试回滚记录，并明确报告回滚失败。
- 编辑完成单独发送 `SLOTS_EDITED`，不触发 `SLOTS_WRITTEN` 的自动生图；刷新缓存和当前楼控件。
- 生命周期释放双击监听、事件订阅与编辑弹窗；查看器关闭时释放键盘监听。
- 双击手势支持主页面 `.mes_text` / `.mes_block` 及嵌套容器、可访问的同源 iframe 空白区域，不接管图片、按钮、输入框和文字选词。跨域 iframe 不在支持范围。
- 未指定“NovelAI 本地前端”的具体项目，采用独立多 Key 池实现，未复制或宣称使用其源码。
