## 2. 层依赖规则

```
L5 ui/  →  L4 application/  →  L3 domain/
                  ↓                 ↑
            L2 ports/ ←── L2 adapters/
                  ↓
             L1 infra/
```

| 层 | 允许 import | 禁止 import |
| --- | --- | --- |
| `domain/` | `infra/` | `adapters/`、`application/`、`ui/`、酒馆任何模块、`fetch`、`document`、`window`、`localStorage` |
| `application/` | `domain/`、`ports/`(仅类型)、`infra/` | `adapters/` 具体实现、`ui/`、`document` |
| `adapters/` | `ports/`、`infra/`、`domain/`（仅模型与纯函数） | `application/`、`ui/` |
| `ui/` | `application/`、`infra/`、`domain/model/` | `adapters/`（一律经用例或端口） |
| `infra/` | 无 | 一切 |

**`domain/` 必须是纯的**：同样输入必得同样输出，不碰时间、随机数、DOM、网络、存储。
需要 id 或时间戳就**从参数传入**，不要在 domain 里调 `Date.now()` / `crypto.randomUUID()`。
（`infra/id.js`、`infra/clock.js` 由调用方注入。）

这条是本架构最主要的风险对冲：酒馆升级时只改 `adapters/host/`，领域逻辑与其测试一行不动。

## 3. 契约纪律（并行开发的生命线）

W0 波次冻结的**契约层**包括：

```
src/infra/**        src/ports/**        src/domain/model/**
```

以及所有其他文件的**函数签名桩**（带完整 JSDoc、体内 `throw new Error('not implemented')`）。

规则：

- **契约层与所有签名一旦冻结，任何人不得擅自修改。** 包括：改参数个数/顺序/类型、改返回类型、改函数名、改文件名、删函数。
- 发现签名有错或不够用 → **立刻停止该项工作，在最终报告的「契约变更申请」一节写明**：
  哪个签名、为什么不行、建议改成什么、影响哪些调用方。由协调者裁决后统一改。
- **可以**在自己目录内新增私有辅助函数与私有文件，不需要申请。
- 填充签名桩时**只改函数体**，不改签名与 JSDoc（JSDoc 有误也走变更申请）。

## 4. 编码规范

### 4.1 风格

- 4 空格缩进；分号必写；单引号；`const` 优先，不用 `var`
- 模块顶层不执行副作用（不自动注册、不自动 DOM 操作）。一切由 `bootstrap/` 显式调用
- **不写 barrel / index.js 再导出**，一律具名导入具体文件（唯一例外：`ports/index.d.ts` 是纯类型）
- 导出一律具名导出，不用 `export default`

### 4.2 JSDoc（强制）

每个导出函数必须有 JSDoc，含 `@param` / `@returns`。跨层的数据结构用 `@typedef` 定义在
`src/ports/index.d.ts` 或 `src/domain/model/*.js` 里，其他地方 `@import` 引用，不重复定义。

### 4.3 错误处理

- **跨层返回 `Result<T,E>`，不抛异常**（见 `infra/result.js`）。理由见架构文档 §10
- 只有「调用方传了非法参数」这种编程错误才 `throw`
- 一切失败都归类到 `infra/errors.js` 的 `AppError` 六个分类之一，且带可操作的用户提示
- 不要 `catch` 后静默；至少 `logger.warn` 并转成 `Result.err`

### 4.4 注释

只在代码本身无法表达约束时写注释：为什么必须这样、宿主的哪条怪异行为迫使如此（带
`宿主能力基线.md §N` 或 `ref/SillyTavern/...:行号` 出处）。
**不要**写「这行做什么」「这里是新增的」「按架构文档要求」这类注释。

### 4.5 命名

- 文件名 `kebab-case.js`；类 `PascalCase`；函数与变量 `camelCase`；常量 `UPPER_SNAKE`
- CSS 全部选择器挂 `#nai-dbgen-root` 前缀，类名前缀 `nd-`（架构文档 §8.2 / §8.3）
- 对外暴露给酒馆的全局名、事件名、存储键一律前缀 `nai-dbgen` / `naiDbGen`

## 5. 测试

- 位置 `tests/`，镜像 `src/` 结构，文件名 `*.test.js`
- 用 **Node 内置** 测试器，命令固定为 **`npm test`**。不装任何测试框架（H2）
  - 不要用 `node --test tests/`：Node 24 会把目录当 ESM 入口去 import 而报
    `ERR_UNSUPPORTED_DIR_IMPORT`。`package.json` 里已配好 glob
- `domain/` 的每个导出函数**必须**有测试，覆盖正常 + 边界 + 非法输入
- `adapters/` 与 `ui/` 不要求单测（依赖浏览器与宿主），但纯函数部分要测
- 测试里不得联网、不得读写真实 IndexedDB

自查：`node --test tests/` 必须全绿才算交付。

## 6. 交付报告格式

每个开发代理最后必须输出：

```
## 交付清单
（文件路径 + 一句话职责；新增/修改标明）

## 契约变更申请
（无则写「无」。有则按 §3 格式逐条写）

## 未实现 / 打桩留待后续
（明确列出，不要假装完成）

## 对宿主行为的新发现
（若读 ref/SillyTavern 时发现与 宿主能力基线.md 不符 → 必报，附 file:line）

## 自测结果
（node --test 输出摘要；无测试则说明原因）
```

**诚实高于完整。** 没做的、拿不准的、和文档冲突的，必须显式报告。
隐瞒问题会在验收波次被独立代理查出来，代价更大。

### D35：出图闸门收归应用层单一咽喉点（阻塞级·重复计费）

W2 验收查出：slot 控件用模块级 inflight 表，自动出图服务用自己的 `rendering` Set，
**两张表互不通信**，而 `renderSlot.execute` 自身没有任何门禁。
手点与自动触发并发 → 同一 slot 双次调 NAI → **双份扣费**。
按钮 `disabled` 挡不住事件路径。

**裁决**：闸门必须落在 `RenderSlotUseCase` 内部——它是 UI 与 auto 的**唯一共同入口**。
两条调用路径各自维护一张表，无论写得多仔细都不可能互斥。
UI 侧的 inflight 表只允许用于**恢复视觉状态**，不得作为计费防线。

`renderSlot.execute` 必须自带：进行中互斥 + 已有图则拒绝重出（除显式 `force`）。

### D36：inflight 键必须带 chatId（阻塞级·跨聊天串台）

酒馆 `messageId` 是**当前聊天数组的下标**，不是全局 ID。切聊天后同一 `(5,1)` 指向另一楼。
后果：B 聊天误显「生图中」、误附着 A 的 promise、或被 A 的结算清掉。

**裁决**：所有以 messageId 为键的缓存/表，键一律为 `chatId:messageId:slotId`。
写盘前必须校验仍是发起时的 chat，不是则丢弃结果而非写错楼。
切聊天时清理本聊天以外的条目。

### D37：先写记录再改正文（阻塞级·正文与记录分裂）

现状先 `replaceMessageText` 再 `slotRepo.put`，`put` 失败不回滚正文
→ 正文留下孤儿 `<IMG>` token，正则照样吐按钮，点下去 `SLOT_NOT_FOUND`。

**裁决**：**先写权威记录，再改正文。**
理由是两种失败的伤害不对称：记录写成功而正文失败，用户什么都看不到（记录不可见，重试会覆盖）；
正文改成功而记录失败，用户看到一个永远点不动的坏按钮。
选伤害小的那一侧。

### D38：自动写入必须幂等，浏览既有 swipe 绝不重新计费（阻塞级）

两个问题：
1. `writing` 只防并发，不防二次 settled。同一楼再次 settled 会重跑完整链路（两次 LLM），
   且 `put(..., images: [])` 会**抹掉已出图记录**。
2. 宿主把 `MESSAGE_SWIPED` 也接成 `onAiMessageSettled`。

**裁决**：
- 应用层：`writeSlots` 前先查该楼是否已有 slot 记录，有则跳过。需求 4.12 明确「改旧楼不触发」
- **区分「新生成的 swipe」与「回翻到已存在的 swipe」**：前者是新正文，生成 slot 合理；
  后者用户只是在看旧内容，**重新计费不可接受**。判据是该 swipe 是否已有记录
- 任何情况下不得用空 `images: []` 覆盖已有出图记录

### D39：读失败不得当成「没有图」（阻塞级）

`auto-trigger` 里 `slotRepo.get` 返回 `Err` 时落入了出图分支。
这是本项目**第四次**踩同一个坑（前三次：作者注释、GC 空输入、messageExtra 读失败）。

**裁决**：凡「查到没有 → 就去做某事」的判断，`Err` 必须与「查到确实没有」分开处理。
读失败一律 `warn` + 跳过，**绝不**触发计费动作。

### D40：类名常量不得从 adapters 反向 import

`ui/slot-widget/` 为拿类名常量 import 了 `adapters/host/slot-mount.observer.js`，违反分层。
**裁决**：常量下沉到 `domain/slot/`，两侧各自 import 领域层。

### D41：不得临时替换共享 port 方法

`generateSlots` 为统计 LLM 次数临时改写 `llm.complete`，`finally` 还原。
并发两路时会互相拆掉对方的包装。
**裁决**：改为注入计数装饰器或按调用传 callback，**禁止改写共享 port 的方法**。

### D42：计费成功后的写盘失败要能只重试写盘

NAI 已出图（已扣费）、blob 已入库，但 `recordImage` 失败 → UI 显示 error → 用户重试 → **再扣一次**。
**裁决**：保留已得到的 `imageRef`，重试路径只重写记录、不重新出图。

### D43：`onGenerateClick` 必须返回 `Promise<Result>`

现状允许返回 `void`，而 `undefined` 被判为成功并清空 inflight → 可再点再发。
**裁决**：签名固定为 `Promise<Result>`；拿到非 Result 视为编程错误，**不清表**（宁可卡住也不重复计费）。

### D44：「导入已勾选」必须真的只导已勾选（阻塞级·数据覆盖）

`ui/common/import-export.js` 的 `commitImport` 把**完整** `pendingData` 交给 `importJson`，
勾选列只当「预览确认信号」。但按钮文案是「导入已勾选」。

**裁决**：按勾选过滤后再提交。
理由：用户取消勾选某条、再选「覆盖已有」，按现状会覆盖他**本想保住**的条目。
UI 承诺了什么就必须做到什么——**假 UI 比没有 UI 危险**，因为用户会依据它做不可逆决定。
策略为 overwrite 时另加二次确认。

### D45：编辑保存不得静默丢字段（阻塞级·数据丢失）

`preset-panel.js` 读入时丢掉 `injection_position` / `injection_depth` / `injection_order`，
写出时写死默认值。从酒馆导入的深度与位置会在「打开编辑 → 保存」后被抹平。

**裁决**：**表单不展示的字段必须原样保留。**
这条是通则，不只针对预设：所有库的编辑保存都要复查一遍。
用户点开看一眼再关掉，数据不该变——这是最基本的信任。

### D46：删掉画师预览的「回滚 activeArtistId」（有害补丁）

应用层 `artist-preview.service.js` 本就不改全局激活态（D9 传 `artist` 对象覆盖）。
面板那段「预览前后比对、若被改则回滚」几乎从不触发；
**一旦真触发，就是在长耗时 NAI 期间把用户刚在抽屉里改的激活串写回旧值。**

**裁决**：删除回滚逻辑。补丁不是根治，而且这个补丁自己就是竞态源。

### D47：4.13 参数必须在两处都可改

需求 4.15 明确「4.13 的参数在这一页都能改」。当前工作台缺 `skip_cfg_above_sigma`、
`tag_hint_transparent_background`；运行配置面板缺更多（`tag_hint_qt`、`tag_hint_uc_preset`、
`cfg_rescale`、`sm`、`sm_dyn`、`straight_alpha` 等）。

**裁决**：按 4.13 表逐项对齐控件。默认值一律取自 `domain/model/nai-params.js`。

### D48：`#nai-dbgen-root` 不得重复

抽屉与管理台各自挂了一个 `#nai-dbgen-root`，两者同时存在时 id 重复，
`getElementById` 与 D30 弹窗兜底的挂载目标变得不确定。

**裁决**：抽屉改用独立 id；令牌挂到共同 class 上，两处各自作用域。

### D52：作用域根一律改用 class `.nd-root`，不用 id（协调者复查追加）

D48 只修了抽屉。协调者复查发现 `nai-dbgen-root` 这个 id 实际在**三处**被赋值：
`ui/common/modal.js`（每个弹窗包装都赋一次）、`ui/panels/shell.js`、`ui/slot-widget/image-viewer.js`。

同时开着管理台 + 一个确认框 + 图片查看器时，DOM 里会有**多个同 id 节点**，
而 `modal.js` 用 `document.getElementById('nai-dbgen-root')` 取——按文档顺序拿第一个，**可能是错的那个**。

**裁决**：作用域根改用 class `.nd-root`，**不再用 id 做样式作用域**。
id 天然是单例语义，而我们的根是**可同时存在多个**的（每个弹窗一个）——用 id 表达多实例从一开始就是错的。
`tokens.css` / `components.css` / 各面板 CSS 的 `#nai-dbgen-root` 选择器一并迁到 `.nd-root`。
需要定位具体容器时传元素引用，不用 `getElementById`。

### D53：`mountImportExport` 增加可选 `confirmOverwrite` 回调

W1-E 的 overwrite 二次确认用了 `window.confirm`，在酒馆里弹原生对话框很突兀且阻塞。
**裁决**：增加可选 `confirmOverwrite` 回调，面板传宿主弹窗确认；未传时才退回 `window.confirm`。

### D49：裸数组导入必须拒绝

`library-logic.js` 对无 `kind` 的裸数组放行，把标签数组贴进画师导入也能过 UI，
错库写入风险下沉到仓储。**裁决**：一律拒绝，强制信封。

### D50：确认框关窗要立即取消

`confirmDanger` 靠 120s 超时才当取消，关窗不点按钮会悬挂。
**裁决**：订阅弹窗关闭回调，立即 `settle(false)`。

### D51：`data:image/svg+xml` 从白名单移除

SVG 可内嵌脚本。当 `img.src` 时现代浏览器一般不执行，但白名单是**跨用途**的，
将来任何一处把它当 `href` 或 `object` 用就直接破防。
**裁决**：白名单收紧为光栅 MIME（`png`/`jpeg`/`webp`/`gif`），禁 `svg+xml`。
安全边界要按最危险的用法划，不按当前用法划。
