## 2. 层依赖规则

```
L5 ui/  →  L4 application/  →  L3 domain/
                  ↓                 ↑
            L2 ports/ ←── L2 adapters/
                  ↓
             L1 infra/
```

| 层 | 允许 import | 禁止 import |
| --- | --- | --- |
| `domain/` | `infra/` | `adapters/`、`application/`、`ui/`、酒馆任何模块、`fetch`、`document`、`window`、`localStorage` |
| `application/` | `domain/`、`ports/`(仅类型)、`infra/` | `adapters/` 具体实现、`ui/`、`document` |
| `adapters/` | `ports/`、`infra/`、`domain/`（仅模型与纯函数） | `application/`、`ui/` |
| `ui/` | `application/`、`infra/`、`domain/model/` | `adapters/`（一律经用例或端口） |
| `infra/` | 无 | 一切 |

**`domain/` 必须是纯的**：同样输入必得同样输出，不碰时间、随机数、DOM、网络、存储。
需要 id 或时间戳就**从参数传入**，不要在 domain 里调 `Date.now()` / `crypto.randomUUID()`。
（`infra/id.js`、`infra/clock.js` 由调用方注入。）

这条是本架构最主要的风险对冲：酒馆升级时只改 `adapters/host/`，领域逻辑与其测试一行不动。

## 3. 契约纪律（并行开发的生命线）

W0 波次冻结的**契约层**包括：

```
src/infra/**        src/ports/**        src/domain/model/**
```

以及所有其他文件的**函数签名桩**（带完整 JSDoc、体内 `throw new Error('not implemented')`）。

规则：

- **契约层与所有签名一旦冻结，任何人不得擅自修改。** 包括：改参数个数/顺序/类型、改返回类型、改函数名、改文件名、删函数。
- 发现签名有错或不够用 → **立刻停止该项工作，在最终报告的「契约变更申请」一节写明**：
  哪个签名、为什么不行、建议改成什么、影响哪些调用方。由协调者裁决后统一改。
- **可以**在自己目录内新增私有辅助函数与私有文件，不需要申请。
- 填充签名桩时**只改函数体**，不改签名与 JSDoc（JSDoc 有误也走变更申请）。

## 4. 编码规范

### 4.1 风格

- 4 空格缩进；分号必写；单引号；`const` 优先，不用 `var`
- 模块顶层不执行副作用（不自动注册、不自动 DOM 操作）。一切由 `bootstrap/` 显式调用
- **不写 barrel / index.js 再导出**，一律具名导入具体文件（唯一例外：`ports/index.d.ts` 是纯类型）
- 导出一律具名导出，不用 `export default`

### 4.2 JSDoc（强制）

每个导出函数必须有 JSDoc，含 `@param` / `@returns`。跨层的数据结构用 `@typedef` 定义在
`src/ports/index.d.ts` 或 `src/domain/model/*.js` 里，其他地方 `@import` 引用，不重复定义。

### 4.3 错误处理

- **跨层返回 `Result<T,E>`，不抛异常**（见 `infra/result.js`）。理由见架构文档 §10
- 只有「调用方传了非法参数」这种编程错误才 `throw`
- 一切失败都归类到 `infra/errors.js` 的 `AppError` 六个分类之一，且带可操作的用户提示
- 不要 `catch` 后静默；至少 `logger.warn` 并转成 `Result.err`

### 4.4 注释

只在代码本身无法表达约束时写注释：为什么必须这样、宿主的哪条怪异行为迫使如此（带
`宿主能力基线.md §N` 或 `ref/SillyTavern/...:行号` 出处）。
**不要**写「这行做什么」「这里是新增的」「按架构文档要求」这类注释。

### 4.5 命名

- 文件名 `kebab-case.js`；类 `PascalCase`；函数与变量 `camelCase`；常量 `UPPER_SNAKE`
- CSS 全部选择器挂 `#nai-dbgen-root` 前缀，类名前缀 `nd-`（架构文档 §8.2 / §8.3）
- 对外暴露给酒馆的全局名、事件名、存储键一律前缀 `nai-dbgen` / `naiDbGen`

## 5. 测试

- 位置 `tests/`，镜像 `src/` 结构，文件名 `*.test.js`
- 用 **Node 内置** 测试器，命令固定为 **`npm test`**。不装任何测试框架（H2）
  - 不要用 `node --test tests/`：Node 24 会把目录当 ESM 入口去 import 而报
    `ERR_UNSUPPORTED_DIR_IMPORT`。`package.json` 里已配好 glob
- `domain/` 的每个导出函数**必须**有测试，覆盖正常 + 边界 + 非法输入
- `adapters/` 与 `ui/` 不要求单测（依赖浏览器与宿主），但纯函数部分要测
- 测试里不得联网、不得读写真实 IndexedDB

自查：`node --test tests/` 必须全绿才算交付。

## 6. 交付报告格式

每个开发代理最后必须输出：

```
## 交付清单
（文件路径 + 一句话职责；新增/修改标明）

## 契约变更申请
（无则写「无」。有则按 §3 格式逐条写）

## 未实现 / 打桩留待后续
（明确列出，不要假装完成）

## 对宿主行为的新发现
（若读 ref/SillyTavern 时发现与 宿主能力基线.md 不符 → 必报，附 file:line）

## 自测结果
（node --test 输出摘要；无测试则说明原因）
```

**诚实高于完整。** 没做的、拿不准的、和文档冲突的，必须显式报告。
隐瞒问题会在验收波次被独立代理查出来，代价更大。

### D35：出图闸门收归应用层单一咽喉点（阻塞级·重复计费）

W2 验收查出：slot 控件用模块级 inflight 表，自动出图服务用自己的 `rendering` Set，
**两张表互不通信**，而 `renderSlot.execute` 自身没有任何门禁。
手点与自动触发并发 → 同一 slot 双次调 NAI → **双份扣费**。
按钮 `disabled` 挡不住事件路径。

**裁决**：闸门必须落在 `RenderSlotUseCase` 内部——它是 UI 与 auto 的**唯一共同入口**。
两条调用路径各自维护一张表，无论写得多仔细都不可能互斥。
UI 侧的 inflight 表只允许用于**恢复视觉状态**，不得作为计费防线。

`renderSlot.execute` 必须自带：进行中互斥 + 已有图则拒绝重出（除显式 `force`）。

### D36：inflight 键必须带 chatId（阻塞级·跨聊天串台）

酒馆 `messageId` 是**当前聊天数组的下标**，不是全局 ID。切聊天后同一 `(5,1)` 指向另一楼。
后果：B 聊天误显「生图中」、误附着 A 的 promise、或被 A 的结算清掉。

**裁决**：所有以 messageId 为键的缓存/表，键一律为 `chatId:messageId:slotId`。
生图过程中切走会话时：
- 权威记录仍写入**发起时那个会话**的服务器文件（按 `sessionId` / integrity 寻址），不写入、不污染当前会话的内存缓存；
- 楼层正文（`replaceMessageText`）只在仍处于同一会话时才改；
- 已出图的不重出、不二次扣费；楼层批量出图在切走后对尚未发起的 slot 记为 skipped，不再开新的 NAI。
切聊天时清理本聊天以外的视觉 inflight 条目。

### D37：先写记录再改正文（阻塞级·正文与记录分裂）

现状先 `replaceMessageText` 再 `slotRepo.put`，`put` 失败不回滚正文
→ 正文留下孤儿 `<IMG>` token，正则照样吐按钮，点下去 `SLOT_NOT_FOUND`。

**裁决**：**先写权威记录，再改正文。**
理由是两种失败的伤害不对称：记录写成功而正文失败，用户什么都看不到（记录不可见，重试会覆盖）；
正文改成功而记录失败，用户看到一个永远点不动的坏按钮。
选伤害小的那一侧。

### D38：自动写入必须幂等，浏览既有 swipe 绝不重新计费（阻塞级）

两个问题：
1. `writing` 只防并发，不防二次 settled。同一楼再次 settled 会重跑完整链路（两次 LLM），
   且 `put(..., images: [])` 会**抹掉已出图记录**。
2. 宿主把 `MESSAGE_SWIPED` 也接成 `onAiMessageSettled`。

**裁决**：
- 应用层：`writeSlots` 前先查该楼是否已有 slot 记录，有则跳过。需求 4.12 明确「改旧楼不触发」
- **区分「新生成的 swipe」与「回翻到已存在的 swipe」**：前者是新正文，生成 slot 合理；
  后者用户只是在看旧内容，**重新计费不可接受**。判据是该 swipe 是否已有记录
- 任何情况下不得用空 `images: []` 覆盖已有出图记录

### D39：读失败不得当成「没有图」（阻塞级）

`auto-trigger` 里 `slotRepo.get` 返回 `Err` 时落入了出图分支。
这是本项目**第四次**踩同一个坑（前三次：作者注释、GC 空输入、messageExtra 读失败）。

**裁决**：凡「查到没有 → 就去做某事」的判断，`Err` 必须与「查到确实没有」分开处理。
读失败一律 `warn` + 跳过，**绝不**触发计费动作。

### D40：类名常量不得从 adapters 反向 import

`ui/slot-widget/` 为拿类名常量 import 了 `adapters/host/slot-mount.observer.js`，违反分层。
**裁决**：常量下沉到 `domain/slot/`，两侧各自 import 领域层。

### D41：不得临时替换共享 port 方法

`generateSlots` 为统计 LLM 次数临时改写 `llm.complete`，`finally` 还原。
并发两路时会互相拆掉对方的包装。
**裁决**：改为注入计数装饰器或按调用传 callback，**禁止改写共享 port 的方法**。

### D42：计费成功后的写盘失败要能只重试写盘

NAI 已出图（已扣费）、blob 已入库，但 `recordImage` 失败 → UI 显示 error → 用户重试 → **再扣一次**。
**裁决**：保留已得到的 `imageRef`，重试路径只重写记录、不重新出图。

### D43：`onGenerateClick` 必须返回 `Promise<Result>`

现状允许返回 `void`，而 `undefined` 被判为成功并清空 inflight → 可再点再发。
**裁决**：签名固定为 `Promise<Result>`；拿到非 Result 视为编程错误，**不清表**（宁可卡住也不重复计费）。

### D44：「导入已勾选」必须真的只导已勾选（阻塞级·数据覆盖）

`ui/common/import-export.js` 的 `commitImport` 把**完整** `pendingData` 交给 `importJson`，
勾选列只当「预览确认信号」。但按钮文案是「导入已勾选」。

**裁决**：按勾选过滤后再提交。
理由：用户取消勾选某条、再选「覆盖已有」，按现状会覆盖他**本想保住**的条目。
UI 承诺了什么就必须做到什么——**假 UI 比没有 UI 危险**，因为用户会依据它做不可逆决定。
策略为 overwrite 时另加二次确认。

### D45：编辑保存不得静默丢字段（阻塞级·数据丢失）

`preset-panel.js` 读入时丢掉 `injection_position` / `injection_depth` / `injection_order`，
写出时写死默认值。从酒馆导入的深度与位置会在「打开编辑 → 保存」后被抹平。

**裁决**：**表单不展示的字段必须原样保留。**
这条是通则，不只针对预设：所有库的编辑保存都要复查一遍。
用户点开看一眼再关掉，数据不该变——这是最基本的信任。

### D46：删掉画师预览的「回滚 activeArtistId」（有害补丁）

应用层 `artist-preview.service.js` 本就不改全局激活态（D9 传 `artist` 对象覆盖）。
面板那段「预览前后比对、若被改则回滚」几乎从不触发；
**一旦真触发，就是在长耗时 NAI 期间把用户刚在抽屉里改的激活串写回旧值。**

**裁决**：删除回滚逻辑。补丁不是根治，而且这个补丁自己就是竞态源。

### D47：4.13 参数必须在两处都可改

需求 4.15 明确「4.13 的参数在这一页都能改」。当前工作台缺 `skip_cfg_above_sigma`、
`tag_hint_transparent_background`；运行配置面板缺更多（`tag_hint_qt`、`tag_hint_uc_preset`、
`cfg_rescale`、`sm`、`sm_dyn`、`straight_alpha` 等）。

**裁决**：按 4.13 表逐项对齐控件。默认值一律取自 `domain/model/nai-params.js`。

### D48：`#nai-dbgen-root` 不得重复

抽屉与管理台各自挂了一个 `#nai-dbgen-root`，两者同时存在时 id 重复，
`getElementById` 与 D30 弹窗兜底的挂载目标变得不确定。

**裁决**：抽屉改用独立 id；令牌挂到共同 class 上，两处各自作用域。

### D52：作用域根一律改用 class `.nd-root`，不用 id（协调者复查追加）

D48 只修了抽屉。协调者复查发现 `nai-dbgen-root` 这个 id 实际在**三处**被赋值：
`ui/common/modal.js`（每个弹窗包装都赋一次）、`ui/panels/shell.js`、`ui/common/image-viewer.js`。

同时开着管理台 + 一个确认框 + 图片查看器时，DOM 里会有**多个同 id 节点**，
而 `modal.js` 用 `document.getElementById('nai-dbgen-root')` 取——按文档顺序拿第一个，**可能是错的那个**。

**裁决**：作用域根改用 class `.nd-root`，**不再用 id 做样式作用域**。
id 天然是单例语义，而我们的根是**可同时存在多个**的（每个弹窗一个）——用 id 表达多实例从一开始就是错的。
`tokens.css` / `components.css` / 各面板 CSS 的 `#nai-dbgen-root` 选择器一并迁到 `.nd-root`。
需要定位具体容器时传元素引用，不用 `getElementById`。

### D53：`mountImportExport` 增加可选 `confirmOverwrite` 回调

W1-E 的 overwrite 二次确认曾用 `window.confirm`，在酒馆里弹原生对话框很突兀且阻塞。
**裁决（现行）**：面板注入异步 `confirmOverwrite`（`confirmAsk` / 单层 dialog，按钮「覆盖」「取消」）。
**禁止** `window.confirm` / `alert` / `prompt`。未传回调则拒绝覆盖（安全默认）。由 `tests/ui/no-native-dialogs.test.js` 约束。

### D49：裸数组导入必须拒绝

`library-logic.js` 对无 `kind` 的裸数组放行，把标签数组贴进画师导入也能过 UI，
错库写入风险下沉到仓储。**裁决**：一律拒绝，强制信封。

### D50：确认框关窗要立即取消

`confirmDanger` 靠 120s 超时才当取消，关窗不点按钮会悬挂。
**裁决**：订阅弹窗关闭回调，立即 `settle(false)`。

### D51：`data:image/svg+xml` 从白名单移除

SVG 可内嵌脚本。当 `img.src` 时现代浏览器一般不执行，但白名单是**跨用途**的，
将来任何一处把它当 `href` 或 `object` 用就直接破防。
**裁决**：白名单收紧为光栅 MIME（`png`/`jpeg`/`webp`/`gif`），禁 `svg+xml`。
安全边界要按最危险的用法划，不按当前用法划。

### D54：写 slot 也要闸门——LLM 也是钱（阻塞级·终审发现）

D35 把闸门收到了 `RenderSlotUseCase`，但那只管**出图**。
**写 slot 走的是另一条路，而它要花两次 LLM。**
楼层按钮无 `disabled`、`generateSlots` 自身无 inflight
→ 连点、或「自动写 + 手点」并发 → **四次 LLM 调用**。

**裁决**：`generateSlots` 加与 `autoTrigger` 同级的写锁，键 `chatId:messageId`（D36 同规则）；
楼层按钮进行中 `disabled`。

这是前五轮的系统性盲区：**我们一直把「计费」等同于「调 NAI」，忘了 LLM 也按 token 计费。**
凡是会发出网络请求且对方收费的动作，都必须有闸门。

### D55：任何直调 `imageGen` 的 UI 都要防重复提交（阻塞级）

工作台出图有进行中禁用，**画师预览没有**——连点就是多次 NAI。
`NaiDbGen.generate`（4.14 对外入口）按设计不经 RenderSlot 闸门，这是对的（对外语义应当直通），
但**插件自己的 UI 不能没有闸门**。

**裁决**：画师预览加进行中互斥。凡插件内 UI 直调 `imageGen.generate` 的地方逐个补。

### D56：`activate` 失败不得留下僵尸斜杠命令（阻塞级）

斜杠注册不在 rollback 里，且酒馆无卸载 API。
`activate` 在注册斜杠之后失败 → 容器已 `dispose`，而 `/naigen` `/naiwb` 仍指向**已死闭包**。
用户敲命令会得到诡异错误而非「插件没起来」。

**裁决**：要么把斜杠注册放到所有可能失败的步骤**之后**，
要么失败时把命令回调换成 no-op 并提示「插件未成功加载」。

### D57：那个测例在为 bug 背书，必须重写

`billing-safety` 里 D41 的「并发两路 `generateSlots`」用例，断言两边**各**计费两次算通过。
它测的是「别改写共享 port」（D41），却顺手把「允许双跑」写成了期望行为。

**裁决**：重写该用例——并发同一楼必须**合计**两次 LLM，不是各两次。
另：`isOk(probe) || isErr(probe)` 这种几乎永真的断言一律删掉。
**一个永不失败的测试比没有测试更糟，因为它制造安全感。**

### D58：空配置起步要能自己走下去（应修）

装上插件、什么都没配时：错误 toast 只显示 `message` 丢掉了 `hint`
（而 `hint` 正是为「告诉用户下一步做什么」设计的），抽屉里又选不了预设。
用户会卡在 `IMAGEGEN_PRESET_UNSET` 且不知道该去哪。

**裁决**：toast 与面板错误一律拼上 `hint`；抽屉补预设选择器。
错误信息的价值不在于准确描述失败，而在于让用户知道下一步点哪。

### D59：控件硬化要覆盖全、且允许在自己作用域内用 `!important`（预览页实测发现）

预览沙箱注入模拟宿主全局皮后实测：
- `.nd-button` / slot 按钮被染成黄底红字 Comic Sans——**扣不住**
- 抽屉主开关走的是 `.nd-toggle-row input`（**无 class**），根本不在 D29 的 `.nd-checkbox-row` 选择器里
- toggle 虽 `opacity:0`,仍被宿主撑到约 48×48

**裁决两条**：

1. **覆盖缺口先补**：`createToggle` 的裸 `input` 必须纳入硬化选择器。
   这不是特异性之争,是**漏了**——先把该管的管上。
2. **允许在 `.nd-root` 作用域内对关键属性用 `!important`**。
   原本我们回避 `!important` 是对的,但理由是「不要污染宿主」；
   而在**我们自己的作用域内**用它,保护的是自己的子树,并不影响宿主任何 UI。
   关键属性限定为：`appearance`、`box-sizing`、`font`、`color`、`background`、`border`、`min-height`、`width`。
   **不要全属性 `!important`**——那才是真的失控。

补充说明：预览沙箱用的 `all: unset !important` 比真实酒馆主题更极端,
所以修完仍可能在某些自定义主题下有残差。但**能挡住的先挡住**,挡不住的靠预览页继续暴露。

### D60：抽屉要响应外部配置变更（预览页实测发现）

沙箱点「空配置起步」后 `loadSettings()` 已清空,**抽屉搜索框仍显示旧的当前项**,直到重挂才更新。
真实场景等价于：用户在管理台改了激活项,抽屉不跟。

**裁决**：抽屉与 `current-picker` 订阅设置变更,或对外提供 `refresh()` 由调用方在设置变更后调用。
两者取其一即可,但**必须有一条路能让外部变更反映到 UI 上**。

### D61：扩充 `!important` 白名单,并把 slot 控件纳入硬化（D59 的续裁）

D59 定的白名单太窄,实测被打穿三处：

1. **`padding` / `border-radius` / `height` / `line-height` 不在白名单**——
   而这几个恰恰是控件「看起来烂掉」的主因（按钮被撑成方角大块）。
   **裁决：白名单扩充为**
   `appearance`、`box-sizing`、`font-family`、`font-size`、`line-height`、`color`、
   `background`、`border`、`border-radius`、`padding`、`width`、`height`、`min-height`、
   **`box-shadow`、`overflow`（D70：压过酒馆 `popup.css` 阴影与 `overflow:visible`，才能单层圆角裁切）**、
   **`min-width`（滚动条滑块最小尺寸，压过酒馆全局 `::-webkit-scrollbar`）**。
   仍然**不许全属性 `!important`**,`display`/`position`/`margin`/`z-index` 等继续不许
   （藏酒馆关闭钮用 JS 设 `style.display`，不用 CSS `display:!important`）。

   **滚动条**：酒馆 `style.css` 无作用域 `::-webkit-scrollbar`（约 0.7rem + 灰滑块）会渗进插件弹层。
   在 `.nd-root` 内用 `--nd-scroll-*` token 统一细滑块 + 透明轨道；**禁止** `scrollbar-gutter: stable`
   （会预留空槽、贴边破坏圆角）。见 `components.css` 滚动条段与 `tests/ui/scrollbar-theme.test.js`。
2. **`.nd-slot__btn` 等聊天区控件不在 `.nd-root` 下,完全没被保护**。
   而 slot 控件是**整个插件最显眼的部分**——它长在聊天楼层里,
   用户第一眼看到的就是它。它反而是最该硬化的。
   **裁决：slot-widget 以自己的作用域根（`.nd-slot`）做同等硬化。**
   理由与 D59 一致：保护自己的子树,不碰宿主任何 UI。
3. **`img`**：宿主的 `filter` / `border-radius:50%` / `max-width` 会把出图毁容。
   **裁决：slot 与面板内的 `img` 纳入硬化**,白名单额外允许 `filter`、`max-width`、`object-fit`。

### D62：残差留档,不追求全胜

宿主主题可写任意 `!important`,理论上打不完。**我们的目标不是全胜,是让常见主题下不出丑**。

### D64：禁止用嵌套 `em` 定字号,改用不累乘的字号令牌（预览页实测发现）

管理台实测量到：「编辑组」字号 **7.34px**、宽度只有 **22px**（三个汉字被截断）,
「删除组」**8.04px**。而同一行的「导入/导出」是正常的 12px。

**根因**：`.nd-root` 上 `font-size: var(--mainFontSize, 15px)`,
子层用 `em` 定字号,**逐层相乘**,嵌套三层就成了 7px。
参考项目用的是硬编码 px（9px/11px）,不会累乘——是我改成 `em` 想让它跟宿主缩放时踩的坑。

**裁决**：

1. **组件样式里不得再用 `em` 定 `font-size`**（`em` 用于 padding/margin 等仍可）。
2. 在 `.nd-root` 上一次性定义字号令牌,**全部从根字号直算,不依赖父级**：
   ```
   --nd-fs-base: var(--mainFontSize, 15px);
   --nd-fs-sm:   calc(var(--mainFontSize, 15px) * 0.86);
   --nd-fs-xs:   calc(var(--mainFontSize, 15px) * 0.78);
   --nd-fs-lg:   calc(var(--mainFontSize, 15px) * 1.2);
   ```
   具体档位与系数由执行代理按参考项目的 px 档位反推,但**必须是 calc 直算,不得 `em` 套 `em`**。
3. **下限保护**：任何文字的最终计算字号**不得低于 11px**。
   宿主字号可被用户调到很小,乘完不能变成不可读。
4. 补测：断言样式表里**没有 `font-size: …em`**（防回归）,
   并在预览页用 CDP 量几个最深嵌套处的实际 px 值。

字号仍跟宿主 `--mainFontSize` 缩放（这是无障碍需求,D63 已定）,只是改为不累乘的算法。

### D66：响应式断点按**容器宽**判断,不得按视口宽（预览页实测发现）

D65 落地后实测：工具栏 `grid-template-columns: 387px 387px`（两列）,折成 **3 行**,
而容器实际有 **812px** 可用宽——参考项目的单行布局约需 750px,**放得下**。

**根因**：断点写成了 `@media (max-width: …)`,按**视口宽**（913px）判断。
但管理台是**弹窗**,弹窗宽 `min(900px, 94vw)`,**视口宽与容器宽是两码事**。
在酒馆里更糟：插件面板可能嵌在抽屉、侧栏或窄容器里,视口却是宽屏。

**裁决**：

1. 插件内部组件的响应式**一律按容器宽判断**,用 `@container`（配 `container-type: inline-size`）。
   本项目已在 slot 控件用过 `@container nd-slot`,沿用同一手法,不要两套。
2. **不得再用 `@media (max-width)` 控制插件内部组件的布局**。
   `@media` 仅可用于真正与设备相关的场合（如 `prefers-reduced-motion`、`hover` 能力）。
3. 工具栏在容器宽足够时**必须单行**。档位参照参考项目
   `minmax(240px,1fr) 150px 140px 140px auto auto`,按本插件实际控件数裁减。
4. 补测：断言样式表里**没有用 `@media (max-width)` 控制库/面板布局**（防回归）。

### D67：画师串卡片封面用 **832:1216** + 卡片图；无图类型不放占位封面

用户实测：画师示例图是 **832×1216**（NAI 竖图）。按 4/5 框 + `object-fit: contain` 会左右露出粉色渐变空条；用小缩略图放大则糊。

**裁决（现行）：**

1. **画师串库卡片**封面 `aspect-ratio: 832 / 1216`，图片 `object-fit: cover`，左右上贴齐卡片边缘；顶角与卡片同半径（封面 `overflow: hidden` / 卡片裁切）。
2. **封面只用卡片图**（宽约 480、按原图比例、webp，文件名 `…_card.webp`）。**有图**时显示卡片图；**无图**时仍保留同比例封面区（浅底 + 居中「无示例图」小字），名称与操作按钮与有图卡对齐。**点开大图才加载原图**。导入导出五字段不含卡片图；导入/手填预览时从原图生成。每条画师串服务器上只有原图 + 卡片图两张。
3. **其它有封面的地方按各自图片实际比例**，不要一刀切 4/5（picker 折叠态当前项仍为方 40×40；下拉 mini-cover 等保持既定尺寸）。
4. **无图类型**（LLM/NAI 配置、预设、标签等）**不**生成封面 DOM / monogram（紧凑文字卡）。与画师串区分：画师串「本来就该有图」，无图也占位；其它类型本来就没有图字段，不留空封面区。

**方法论裁决：**

照搬样式不得只看 grep 到的第一条声明。必须比对层叠后的生效值；画师串封面比例以真实 NAI 图尺寸为准，不以参考项目被覆盖掉的 4/3 或桌面 4/5 一刀切。

### D69：圆角四档递减 + pill；禁止写死 px

**问题**：曾出现 `--nd-radius-card: 20px` 大于包它的 `--nd-radius-modal: 18px`（层级倒挂）；档位过多且散落 `border-radius: Npx`。

**裁决（现行）：**

1. **令牌只留五名**（`tokens.css`，slot 镜像同值）：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--nd-radius-lg` | `16px` | 弹窗 / 抽屉 / 大面板（含悬浮球菜单壳） |
| `--nd-radius-md` | `12px` | 卡片、分组容器、详情封面、图片查看器内图 |
| `--nd-radius-sm` | `8px` | 按钮、输入框、下拉、搜索框、标签页、slot 按钮 |
| `--nd-radius-xs` | `6px` | 小徽标、关闭钮、复选框、嵌套在 sm 内的更小控件 |
| `--nd-radius-pill` | `999px` | 药丸形（chip / toggle 轨等） |

2. **层级**：外层圆角 ≥ 内层；嵌套时内层用更小一档（约等于外层 − 间距），禁止同容器叠两档不同圆角「露馅」。弹层内容区半径为 `0`，只靠 shell 裁切。

4. **写死禁止**：`src/ui/**/*.css` 的 `border-radius` 只允许 `var(--nd-radius-*)`、`50%`（圆形球/头像）、`0`。由 `tests/ui/radius-tokens.test.js` 约束。

### D70：弹窗只有一层可见容器（消灭「方框里套圆角」）

**问题**：酒馆 `dialog.popup`（深色底 / 自带 padding·边框·圆角或主题方角）里再套插件 `.nd-native-dialog__shell`（白底 + `--nd-radius-lg`），四角露出外层方角。
